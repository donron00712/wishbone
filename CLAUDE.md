# sweetslips

Marketing site for an advertising medium: brands buy the **printed slip** that
reaches the customer with the restaurant check — their line, their code and the
lucky numbers, set to brief. The audience is media buyers, not diners.

**The site does not name a food, on purpose.** It said fortune cookie, then
kuzhalappam, then cannoli, and each change meant rewriting every headline,
description and schema field. The slip is what is actually sold and the one
thing that survived all three, so the copy is written around it. If the medium
changes again, nothing here has to.

Live at https://sweetslips.co. The repo is `donron00712/wishbone` and it is
**public**.

The brand was **Kismat Cookies** on `kismatcookies.com` until Oct 2026. The
name is written **all lowercase** — `sweetslips`, never `SweetSlips` or
`Sweet Slips` — including at the start of a sentence. `kismatcookies.com`
301s to the new domain while the owner still holds it; they intend to let it
lapse once the move is finished, which is when those redirect rules in
`vercel.json` can go.

## The one rule that will bite you

**Edit `src/pages/*.html`. Never edit the `*.html` in the repo root.** Those are
generated by `build.js` and are overwritten on every build. Content lives in
`assets/js/data.js`.

```bash
npm run build    # regenerate the root pages from src/pages + data.js
npm start        # build, then serve on :4321
npm run add-photo <file>   # crop/compress an image for the hero wall
npm run add-video <file>   # encodes mp4/webm/poster — no consumer right now
npm run og                 # re-render assets/media/og.svg to the share card
```

`build.js` also writes `robots.txt`, `sitemap.xml`, and a `<!--#social-->` block
of canonical/OG/Twitter tags into every page's `<head>`. All three are derived
from the pages themselves, so a new file in `src/pages/` is canonical, shared
and crawlable with nothing else to remember. Canonical host is
`https://sweetslips.co`; `vercel.json` redirects `www`, both old
`kismatcookies.com` hosts and the old Vercel URL to it.

Regions between `<!--#name-->` and `<!--/#name-->` are filled by `build.js`:
`header`, `footer`, `ooh`, `reasons`, `formats`, `targets`, `cases`.

## Structure

- `src/pages/` — page templates (the source)
- `assets/js/data.js` — all copy and content, single source
- `assets/js/site.js` — shared behaviour only; it does **not** build DOM
- `assets/js/home.js` — the hero sequence, the wall, the unit slip
- `assets/css/style.css` — everything, token-driven
- `build.js` — assembles header/footer/cards at build time.

  **Nothing is drawn anywhere on this site, and nothing should be.** Four
  passes once tried to draw the product — a hollow tube, a tighter rim, a
  sealed wrapper, a paper bar — all for an overlay that no longer exists. Every
  one invented an object so there was something to tap, and every one looked
  it. If the artwork ever needs to show the food, that is a photograph, not a
  path.

- Pages: index, formats, why-it-works, cases, contact
- `HIDDEN` in `build.js` lists pages that still build and still answer on
  their URL, but are kept out of the nav, out of `sitemap.xml`, and marked
  `noindex`. `cases` is in it. Delete the name to put a page back.

## One palette

**Dark roast only.** `#2E1D0C` ground, `#F0E3CC` type, on `:root`. Nothing reads
a colour directly — every component goes through tokens.

There used to be a second, beige palette on `[data-theme="warm"]`, flipped by
the fortune moment. Both are gone: the moment was removed in Oct 2026 and the
warm palette went with it, since nothing was left to trigger it. Its values are
in git if they are ever wanted back — see the commit that removed them.

Contrast has been checked pair by pair and everything clears its guideline.
**Check any colour change with a contrast calculation before committing it** —
several rounds were lost to palettes that looked right and measured badly.

`--ink` means "text on the `--text`-coloured surface". `--on-gradient` is
separate, for the always-light card gradient.

## Testing note that will save you an hour

The Claude Code browser pane **freezes CSS animations and transitions** — the
document timeline does not advance. Computed styles read mid-transition values
and screenshots often come back blank. Verify by:
- disabling transitions (`* { transition: none !important }`) before reading
  computed styles, and
- scrubbing animations via `getAnimations()[0].currentTime` rather than waiting.

Several "bugs" this session were this artifact, not the code.

## Honesty constraints that have been held to

- Brand names in the wall are **illustrative** and labelled as such.
- `cases.html` shows real campaigns run by **OpenFortune**, credited on every
  card, with a note stating sweetslips has no relationship with those brands. Do not
  restate them as our own work.
- No invented statistics, no behavioural promises, no launch-status language.
- Photography **and footage** must be shot by us, licensed, or permitted in
  writing. Instagram screenshots are none of those; `assets/media/Screenshot_*`
  and `assets/media/images/` are both gitignored so they cannot reach the
  public repo by accident. The second rule exists because the screenshots came
  back once renamed to `1.png`–`10.png`, which the first rule did not catch.
- **No third-party brand marks in the wall.** Two of the images offered for it
  carried real chains' branded fortune slips (Panda Express, Wing's). A wall
  selling branded fortune cookies cannot show another company's without reading
  as a client list, and no disclaimer fixes that.
- **The wall currently has no pictures at all.** `photos` in `data.js` is an
  empty array and the wall falls back to slips alone. `wall-01`–`wall-08` were
  taken down because they were not ours to publish. Do not restore them from
  history — get licensed images, or shoot them.
- Note that removing them from `HEAD` does not remove them from a public git
  history: they remain reachable at `bee3f90`, and the three stock photographs
  before them at `505488e`. Cleaning that up needs a history rewrite and a
  cache purge, or a fresh repo.

## Removed in Oct 2026

The **fortune moment** — the overlay that interrupted the landing page, gave
the visitor a fortune and turned the site beige — is gone at the owner's
request, along with the warm palette it existed to deliver. With it went the
night sky (46 stars, 14 motes, 2 shooting stars), the aura, the auto-close
timer, the `wb-theme`/`wb-toured` session machinery and the "Back to dark"
footer control. 292 lines of CSS, 134 of `site.js`, 82 of emitted markup.

Two leftovers worth knowing about:

- `assets/media/moment-film.{mp4,webm,jpg}` — 4.3 MB, now referenced by
  nothing. They are fortune-cookie footage from before the medium changed, so
  they were already unusable. Safe to delete.
- `add-video.js` and `npm run og` still work, but `add-video` encodes to the
  4:5 frame the moment wanted and now has nowhere to put the result.
